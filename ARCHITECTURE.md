# Архитектура Monitoring Bot V3

## Поток данных

```text
Telegram / CLI / встроенный scheduler
                 |
                 v
 Google Apps Script + локальный Excel
                 |
                 v
 normalization -> matching -> ReportDocument
                 |
       +---------+---------+
       v         v         v
      TXT       HTML      JSON
       |
   +---+-------------------+
   v                       v
Telegram и канал     SMTP по расписанию
```

`matching.py` и правила девяти полей не зависят от интерфейса и в Sprint 005 не
изменялись. `reporting.py` представляет TXT компактно, по одной строке на объект;
HTML и JSON остаются структурированными.

## Модули

| Модуль | Ответственность |
|---|---|
| `config.py` | `.env`, пути, timezone, Telegram, Google и SMTP |
| `time_windows.py` | последние часы, семь точных форматов и полные сутки |
| `google_client.py` | данные мониторинга, получатели и времена расписания |
| `collateral.py` | read-only потоковое чтение Excel |
| `normalization.py`, `matching.py` | адреса, кадастр и три группы результата |
| `reporting.py` | единый документ, TXT/HTML/JSON |
| `report_service.py` | формирование и уникальное сохранение комплекта файлов |
| `recipients.py` | проверка и дедупликация email |
| `email_delivery.py` | текстовое SMTP SSL письмо |
| `automation.py` | валидация `HH:MM`, следующий запуск и JSON-состояние |
| `channel.py` | безопасная публикация событий и частей отчёта |
| `telegram_bot.py` | авторизация, UX, `/status`, планировщик и автоматическая доставка |

## Telegram и состояния

Авторизация хранится в персональном `user_data` до перезапуска. Секрет
сравнивается как UTF-8 bytes через `hmac.compare_digest`; регистр и пробелы
значимы. Все команды и callbacks проверяют авторизацию.

Состояния ввода интервала, email и времени также находятся в `user_data`, поэтому
пользователи не влияют друг на друга. Ручной мониторинг вызывает только общий
генератор и Telegram/канал; пути к SMTP из него нет.

Синхронные HTTP, Excel и SMTP выполняются через `asyncio.to_thread`, поэтому
цикл Telegram остаётся доступным. Отдельная задача через 15 секунд редактирует
исходное сообщение прогресса и отменяется при завершении или ошибке операции.
Итоговый статус редактирует то же сообщение; ошибки Telegram API изолированы.

## Планировщик

Планировщик запускается и останавливается вместе с Telegram Application. Каждые
15 секунд он читает актуальные времена из Google Sheets. Слот имеет ключ
`YYYY-MM-DDTHH:MM`; после первого срабатывания ключ сохраняется в локальном JSON.
Это предотвращает повтор в цикле и после быстрого перезапуска. Пропущенные слоты
не исполняются задним числом.

Один `asyncio.Lock` не допускает пересечения автоматических запусков. Ошибка
получения данных или отчёта завершает сценарий до SMTP. Пустой список адресатов
фиксируется как результат без SMTP-вызова.

`StateStore` атомарно заменяет JSON-файл и хранит только:

- включена ли рассылка;
- последний минутный слот;
- время и результат последнего мониторинга;
- время и результат последней почтовой попытки.

## Контракт Google

Листы `ОБЪЕКТЫ` и `АНАЛИЗ` только читаются. Столбцы листа `Настройки`
независимы: `A2:A` — email, `B2:B` — время. Apps Script выполняет операции под
Script Lock, не удаляет строки и очищает только выбранную ячейку.

Для времени читаются одновременно сырое и отображаемое значения Google Sheets.
Текст `8:00`, `08:00`, числовая доля суток и ячейка типа «Время» приводятся к
`HH:MM`. Непустое некорректное значение возвращает строковую диагностику.

Существующие действия сохранены. Добавлены `read_schedule_times`,
`add_schedule_time`, `delete_schedule_time`. Локальный файл нужно вручную
развернуть новой версией существующего V3 web app.

## Служебный канал и ошибки

`ChannelPublisher` отключён при пустом `TELEGRAM_MONITORING_CHANNEL_ID`.
Публикация длинного текста последовательна и без потери частей. Исключения
Telegram поглощаются после безопасного технического логирования типа ошибки;
они не меняют результат мониторинга и SMTP. В канал не передаются конфигурация,
секреты или авторизационные сообщения.
