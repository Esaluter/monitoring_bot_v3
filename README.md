# Monitoring Bot V3

Локальный Telegram-бот мониторинга залогового имущества. Он читает новости через
отдельный Google Apps Script, сопоставляет объекты с локальным Excel, создаёт
HTML/JSON/TXT и выполняет автоматическую почтовую рассылку по расписанию.

## Установка и запуск

Требуется Python 3.11 или новее.

```powershell
cd C:\Users\Admin\Desktop\monitoring_bot_v3
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python run.py
```

Остановка — `Ctrl+C`. Планировщик работает внутри процесса Telegram-бота;
отдельный процесс запускать не нужно. Пропущенные во время остановки отправки не
выполняются задним числом.

## Конфигурация

Обязательны параметры источника, Excel, Telegram и SMTP из `.env.example`.
Дополнительные параметры Sprint 005:

```dotenv
TELEGRAM_MONITORING_CHANNEL_ID=-1001234567890
AUTOMATION_STATE_FILE=data/automation_state.json
```

Канал необязателен. Файл состояния не содержит токенов или паролей; в нём
хранятся только признак включения рассылки и результаты последних операций.
Рассылка по умолчанию выключена.

## Telegram

После `/start` пользователь вводит точное значение `TELEGRAM_SECRET_WORD`.
Авторизация персональна и действует до перезапуска. Главное меню:

- `🔎 Сделать мониторинг` — последние 12 часов или ручной интервал;
- `✉️ Настроить письма` — получатели, расписание и включение рассылки.

Ручной мониторинг только формирует и показывает компактный TXT. Он не вызывает
SMTP. Бот редактирует одно сообщение прогресса: сначала показывает формирование,
через 15 секунд — `😹 Я не завис. Работа продолжается…`, затем итоговый статус.

Команда `/status` показывает состояние рассылки, расписание, ближайший запуск,
получателей, последние результаты и настройку канала. Кнопка проверки канала
публикует одно тестовое служебное событие.

Поддерживаемые интервалы:

```text
10.10.2026 15:00 - 11.10.2026 16:00
10.10.2026 1500 - 11.10.2026 1600
10102026 1500 11102026 1600
101020261500-111020261600
10.10.26 15:00 - 11.10.26 16:00
10.10.2026 - 11.10.2026
10102026-11102026
```

Интервал без времени охватывает полные календарные сутки, включая весь
последний день. Часовой пояс по умолчанию — `Asia/Yekaterinburg`.

## Google Apps Script

Локальный исходник находится в `apps_script/Code.gs`. Он не изменяет рабочие
листы `ОБЪЕКТЫ` и `АНАЛИЗ`. Лист `Настройки` использует независимые столбцы:

- `A1` — `Получатели письма`, значения в `A2:A`;
- `B1` — `Время отправки`, значения `HH:MM` в `B2:B`.

Для Sprint 005 / Hotfix 001 нужно вручную заменить код отдельного V3 Apps Script содержимым
`apps_script/Code.gs`, сохранить и создать новую версию существующего
web-развёртывания. URL `/exec`, `V3_SPREADSHEET_ID` и `V3_API_KEY` сохраняются.
Нельзя обновлять скрипты других проектов.

Новые обратно совместимые действия API:

- `read_schedule_times`;
- `add_schedule_time`;
- `delete_schedule_time`.

Прежние действия чтения данных и управления получателями сохранены.
Hotfix принимает текстовые значения и ячейки типа «Время», включая `8:00` и
`08:00`, и нормализует их к `HH:MM`. Некорректная ячейка возвращает ошибку с
номером строки вместо молчаливого пропуска.

## Автоматическая рассылка

В каждое время из `Настройки!B2:B`, если рассылка включена, бот:

1. формирует отчёт за последние 12 часов;
2. публикует полный отчёт в служебный канал, если он настроен;
3. заново читает всех получателей из `A2:A`;
4. отправляет компактный текстовый отчёт одним SMTP-письмом;
5. сохраняет время и результат попытки.

Пустой корректный отчёт отправляется. Включение разрешается только при наличии
хотя бы одного получателя и одного корректного времени. При ошибке мониторинга SMTP не вызывается.
При пустом списке получателей попытка фиксируется без обращения к SMTP. Одно
время срабатывает не более одного раза в минутный слот; параллельные
автоматические мониторинги блокируются.

## Служебный канал

Создайте частный или публичный канал, добавьте существующего бота администратором
с правом публикации и укажите числовой ID в
`TELEGRAM_MONITORING_CHANNEL_ID`. Полные отчёты разбиваются без потери текста.
Ошибка канала записывается в технический лог, но не отменяет мониторинг или
почтовую доставку. Секреты и сообщения авторизации не публикуются.

## Отчёты и диагностика

TXT содержит до трёх фиксированных разделов. Один объект занимает строку с
префиксом `- `; непустые значения девяти бизнес-полей идут в согласованном
порядке через `; `. Пустой третий раздел полностью скрывается.
HTML и JSON сохраняют девять структурированных полей.

```powershell
python -m monitoring_bot_v3 check-google
python -m monitoring_bot_v3 check-excel
python -m monitoring_bot_v3 check-matching --lookback-hours 12
python -m monitoring_bot_v3 generate-report --interval "10.10.2026 - 11.10.2026"
python -m monitoring_bot_v3 list-recipients
```

Пример TXT:

```text
1. Происшествия с залоговым имуществом (29.10.2026)

- АО Пример; Свердловская область; Екатеринбург; ул. Ленина, д. 1; 66:41:0303001:1; ID-1; пожар; В залоге — кадастровый номер

2.Основное в инфополе

- ООО Объект; Пермский край; Пермь; ул. Мира, д. 2; пожар; Не в залоге
```

## Тесты

```powershell
python -m compileall -q monitoring_bot_v3
python -m unittest discover -s tests -v
```

Тесты используют заглушки Google, Telegram и SMTP и не выполняют реальные
публикации или отправки.

## Известные ограничения

- адреса сопоставляются консервативно, без fuzzy matching и геокодирования;
- ИНН отсутствует в текущих контрактах источников и остаётся пустым;
- авторизация Telegram хранится только до перезапуска;
- расписание опрашивается из Google Sheets, поэтому требуется доступ к Apps
  Script; пропущенные отправки не восстанавливаются;
- состояние хранится локально и рассчитано на один процесс приложения;
- обновление Apps Script и добавление бота в канал выполняются пользователем
  вручную.
